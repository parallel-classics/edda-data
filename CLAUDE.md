# CLAUDE.md — edda-data

Purpose: this repository is the citable dataset of Open Edda — the source texts, the aligned rows,
the human corrections (overlays) and the image records. It holds data and one validator, no pipeline.
The pipeline and the website are in the sibling repository `edda-site` (expected at `../edda-site`).

## Hard rules

1. `sources/` and `aligned/` are immutable from your side. Never edit them by hand. `aligned/*.json` is
   generated by the edda-site pipeline; if a row is wrong, the fix is an overlay record, not an edit.
2. Every human change to a text goes into `overlays/<cell>/<file>.json` as a record keyed by row id and cell.
   Never change or delete an existing overlay record; add a newer one (set `replaces` to what it supersedes).
3. Keep status labels honest. A record carries `origin` (`edition`, `published` + `source`, `machine`, `ai`,
   `contributor`) and `check` (`aligned-auto` / `aligned-checked` for published text; `unreviewed` / `reviewed` for
   the rest; `disputed`); the old one-word `status` (`auto`, `draft`, `reviewed`, `disputed`) is still read, never
   written anew. Never write `reviewed` for machine output or for an AI draft; AI text is `origin` `ai`, `check`
   `unreviewed`, with an `author` of the form `ai:<model>-<yyyy-mm>`. `aligned/sources.json` names the sources.
4. Row ids (`<p>-c<chapter>-<row>`, p in p/g/s/h; poems `<poem>-s<stanza>` and `<poem>-p<k>`, e.g. `vsp-s19`) never change. A split row gets a letter suffix
   (`s-c11-4a`); the old id keeps resolving. Never renumber.
5. Do not add dependencies. Scripts are Python 3.11+ standard library, run with `python -I`.
6. Run `python -I scripts/validate.py` before you finish; it must print `OK` and exit 0.
7. Never put partner names, emails or private notes here. This repository is public. The maintainer's email
   appears only in `CITATION.cff`.

## Map

```
sources/{on,is,en}/   base texts as fetched + parsed JSON (sources/README.md: provenance)
aligned/al_*.json     one file per part; rows = {on, is, en, is_cont, en_cont, s_en, s_is, en_draft?}
aligned/poetic/       al_<poem>.json (45 poems; rows carry id, stanza, en_stanzas, quoted_in, head?), index.json, links.json
aligned/titles.json   chapter and poem titles per language (on, is, en, …) with a status per language
auto/                 modernizer.json, is_*_auto.json, en_draft.json (AI draft as produced)
overlays/{on,is,en}/  {"_note": ..., "records": [ {row, cell, text, status, author, date, reason, replaces} ]}
images/               scenes.json (briefs), records.json (verified PD images), pd/ (image files), worlds/ (the map of the worlds)
entities/             the names of the Eddas keyed to Wikidata (entities/README.md); paths/  reading paths of the Start here page
scripts/validate.py   structural checks + status table;  scripts/drafts_to_overlays.py  auto/en_draft.json -> overlays/en/
docs/DATA_MODEL.md    ids, rows, overlays, statuses, how the build applies overlays
docs/STATUS.md        current status table + known issues;  docs/ROADMAP.md  phases and gates for the data
```

## Conventions

- JSON: UTF-8, `ensure_ascii=False`, `indent=1`, LF line endings, trailing newline. Keys as in DATA_MODEL.md.
- Markdown: British spelling, plain, no marketing language.
- Dates `YYYY-MM-DD`. Authors: `user:<handle>` for people, `ai:<model>-<yyyy-mm>` for drafts, `bot:<name>` for tooling.
- Overlay files are grouped per part and origin, e.g. `overlays/en/hattatal-ai-draft.json`,
  `overlays/is/skaldskaparmal.json`. One record per (row, cell) edit; verse lines separated by `\n`.
- Commit messages name the row ids touched when there are few, the part and count when there are many.
- Being found (edda-site `docs/specs/SEO.md`): the text a reader sees first is also what a search result and an
  assistant (ChatGPT, Claude) quote. The first sentence of an entity summary, a guide card's hook, a story's hook or
  an intro says who or what in plain words and stands on its own; the English form of a name (`names.en`) and the
  Wikidata id of an entity go into the page's title and JSON-LD, so keep them filled and right.
- Entity, card, story and tour ids are parts of URLs (`/names/<id>/`, `/mimir/<id>/`): renaming or removing one
  needs a redirect in edda-site, so say so in the PR.

## Commands

```
python -I scripts/validate.py                  # all checks + status table; exit 1 on errors
python -I scripts/drafts_to_overlays.py        # regenerate overlays/en/*-ai-draft.json from auto/en_draft.json
```

## What "done" looks like

- Adding a correction: a new record in the right `overlays/<cell>/` file, status `draft` (or `reviewed` only
  if a reviewer with the right role accepted it), validator OK, `docs/STATUS.md` left for the next release
  build (it is regenerated from the validator output, not edited by hand except the known-issues list).
- Adding an image: a record in `images/records.json` with all keys (see `images/README.md`), the file in
  `images/pd/` if hosted here, `license_basis` and `checked_by` filled, validator OK.
- Re-importing aligned rows (maintainers only): comes from `edda-site` as a pull request; row ids must be
  unchanged or suffixed; `CHANGELOG.md` updated.
- A release: `CHANGELOG.md`, `CITATION.cff` version and date, `docs/STATUS.md` table refreshed, tag `X.Y.Z`.
